## Design Specificity Verdict

**Not authored for The Graph, and not authored for oracle-eligibility monitoring.** Swap four strings and this is a Kubernetes node list or a validator monitor.

**LLM assessment.** The generic signature is structural, not chromatic:
- Purple→blue gradient body with a white rounded card floating on it (`generate_dashboard.py:84`) — the canonical 2019 template signature. thegraph.com does not do this. In dark theme it produces a bright purple frame around a Galaxy-Dark card; the gradient never learned about the theme.
- Everything centered. Title, subtitle, environment control, contract info, metadata, banner, counters, legend. Centering is what you get when no one chose an axis.
- Four undifferentiated counters in a `space-around` flex row (`:2858`) — no cards, no deltas, no indication that three of the four are *parts* of the first.
- A 6-column, 98-row unpaginated table at 59.4px row height. Total document height **7,109px**. That's a dump, not a view.
- A separate "Status Legend" card between the controls and the table — a legend exists because the badge can't explain itself.
- `font-family: 'Courier New', monospace` on every address (`:2515`) — 98 repetitions of the loudest "not designed" signal available.
- `<h1>🍪 REO</h1>` (`:2801`). A cookie emoji is the wordmark.

**Brand/GDS fidelity.** Real licensed Euclid Circular A (10 weights, self-hosted, no CDN) and correct `light-dark()` token plumbing are genuinely right. Against that:
- **Zero GDS type tokens.** `var(--text-1x)` → 0 uses. Every size is a literal: `14px`×16, `12px`×7, **`13px`×5**, `1.1em`. `13px` and `17.6px` are off the GDS scale entirely.
- **The status system runs on Tailwind/Material defaults, not brand.** Green: `#4BCA81` (brand) + `#22c55e` + `#4CAF50` + `#45a049`. Yellow: `#FFA801` (brand) + `#fbbf24` + `#eab308` + `#FF9800`. Red: `#ef4444`. Gray `#9CA3AF` appears **20×** — the most-used color in the file. The token swap re-skinned the chrome and left the *subject of the product* on stock utility colors.

Expired and Unqualified become the identical pink pill — collapsing the exact distinction the four-state model exists to make. On all 98 rows.

## Overall Impression

The plumbing is better than the product. Theme wiring, self-hosted licensed fonts, and the four-state eligibility model are all sound — and worth keeping through a rebuild. What's broken is everything between the data and the eye: a centered gradient card wrapping a raw table, a status system on stock Tailwind colors that fails contrast in the theme it ships by default, and no identity, no empty states, and no answer to the one question the primary user actually has.

The single biggest opportunity: **the page has no vocabulary for the moment that matters.** An indexer three days from losing rewards eligibility gets a 12px orange pill at 1.75:1 contrast, an absolute timestamp they must diff by hand, and no path to remediation. The 14-day grace countdown — the defining number in GIP-0079 — is never computed anywhere in the UI.

## What's Working

1. **Theme plumbing is correct and non-obvious.** The pre-paint script (`output/index.html:12`) stamps `.gds-light`/`.gds-dark` before first paint — no FOUC. The `--reo-*` aliases (`:1735`) each carry a hex fallback so the page survives a missing `gds.css`. The "token kitchen-sink" block (`:1726`) is a correct solution to Tailwind v4's scan-based token emission. **Keep this layer.**
2. **Real licensed Euclid Circular A, self-hosted, 10 weights, zero CDN calls.** `font-display: swap` on all rules, no FOIT. Fully offline-capable — which matters for a file regenerated every 5 minutes into a static volume.
3. **The four-state model is the right domain decomposition.** Separating `eligible-grace` from `eligible-active`, and `ineligible-expired` from `ineligible-unqualified`, is exactly right: "you lapsed" and "you never qualified" demand different actions. The information design is sound; only its visual expression fails it.

## Priority Issues

**[P0] Every status color fails WCAG AA in the default theme, and the ineligible badge is broken by an invalid hex.**
- **Why it matters:** The status is the entire product. The table reuses the legend's classes verbatim — a real cell is `<td><span class="legend-badge ineligible">`. Measured in light: Grace filter **1.50:1**, Grace badge **1.75:1**, Active badge **1.87:1**, Grace counter **1.92:1** (32px, needs 3.0), Reset **2.16:1**, active sort **2.28:1**, muted `#9ca3af` **2.54:1** across 6 elements, Ineligible filter **2.89:1**, contract link **3.57:1**. Fifteen failures of 43 elements in light; only four in dark. These colors were designed against a dark canvas and shipped on a white one. Separately, the invalid hex kills the ineligible border, making Expired and Unqualified indistinguishable.
- **Fix:** Derive per-status *pairs* per theme from GDS semantic tokens — fill and text designed together, not one fixed text color over a 15%-alpha wash. Use Starfield Green / Solar Yellow as fills with dark text in light theme. Give Expired and Unqualified distinct treatments. Delete `--graph-red`; The Graph has no red — Nebula Pink `#FF79C6` or a sonja step is the branded route.
- **Command:** `/impeccable colorize`, then `/impeccable audit`

**[P0] 9 of 13 primary controls have no visible focus ring, and all 6 sortable headers are mouse-only.**
- **Why it matters:** Measured by real `Tab` traversal (not programmatic `.focus()`). Two suppression mechanisms: `outline-style: none` on the environment select, theme toggle, and search input; `outline-width: 0px` on all four filter buttons and both sort buttons. Only links get a ring. `:focus-visible` count in `index.html`: **0** — GDS ships correct base focus rules at `gds.css:1449`, and the dashboard's inline `<style>` overrides them. Separately, the 6 `<th class="sortable">` have click handlers and `cursor: pointer` but no `tabindex`, no `role`, no `aria-sort` — sorting is unreachable by keyboard and its state is unannounced. With 1 `aria-label`, 1 `<label>`, and 0 `aria-live`/`aria-sort`/`aria-pressed` in the entire document, plus zero landmarks and an h1→h3 skip, this page is not operable by keyboard or screen reader.
- **Fix:** Stop overriding GDS focus rules. Make sortable headers real `<button>`s inside `<th scope="col">` with `aria-sort`. Label the search input. Add `<main>`/`<header>`/`<footer>`, an h2 level, a `<caption>`, and an `aria-live` region for the row count.
- **Command:** `/impeccable harden`, then `/impeccable audit`

**[P1] There is no empty state, no error state, and no loading state.**
- **Why it matters:** Verified live — filtering to zero results renders a bare table header over blank space and `Showing: 0` in 14px footer text. No "no results" string exists anywhere in source. The only fallback copy is the literal `Contract: Loading...` / `Deployed: Loading...` placeholders (`:2822`), which is what users see permanently if the JS env bootstrap fails. The local build's 98 identical "Unqualified" pills are indistinguishable from "the oracle is broken" and from "this network has no data yet" — a dashboard about eligibility has no vocabulary to tell those apart.
- **Fix:** Three explicit states with copy that distinguishes them: "No indexers match this filter" + Reset; "No oracle data for Arbitrum Sepolia yet"; "Couldn't reach the oracle — showing data from HH:MM".
- **Command:** `/impeccable harden`

**[P1] No The Graph identity, and no self-service path for the indexer.**
- **Why it matters:** Two sides of one failure — the page doesn't say whose it is, and it doesn't let an individual make it theirs. No logo, no favicon, generic `<title>`. Zero URL state, so the Telegram bot's alerts can only link to the page top, never to the affected indexer. No copy-address, no per-indexer view, no countdown. Together these are most of "doesn't feel like a native thegraph.com web app."
- **Fix:** Wordmark, favicon, `<title>Rewards Eligibility Oracle · The Graph</title>`, OG tags. Then `?indexer=0x…` and `?network=&status=` deep links, a pinned "your row", copy buttons on addresses, and a computed "N days left" on every Grace row.
- **Command:** `/impeccable shape`, then `/impeccable clarify`

**[P2] Mobile header text collision; table columns hidden behind a 270px scroll container.**
- **Why it matters:** `#contract-address` computes to **1.94px wide** with `display: block` and `overflow: visible` inside a 74.9px parent — its text paints outside its box and overlaps the "Deployed:" sibling. Screenshot-confirmed in both themes. "Environment:" is clipped mid-word by the adjacent select. The table is correctly contained (`overflow-x: auto`, no page-level overflow — the document measures 390/390), but its container is 270px against 826px of content, so Status, Streak, Last Renewed, and Eligible Until all require horizontal scrolling to reach. 110 touch targets are under 44×44 (98 table links at 14px tall; filter buttons 33px). One breakpoint exists in the whole stylesheet, several of whose rules target classes absent from the markup.
- **Why it compounds:** Indexers get Telegram alerts. Alerts open on phones. The mobile view of the alert's destination hides the answer.
- **Fix:** Card-per-row below 768px with Status promoted to the top of each card. Add a real intermediate breakpoint. Delete the dead rules.
- **Command:** `/impeccable adapt`

**[P3] Cross-environment link leak.** `chain=arbitrum-one` hardcoded at `:2974` and `:3614`; verified all 99 Explorer links on the Sepolia view point at mainnet. Derive the chain slug from the selected environment.

## Persona Red Flags

**Alex (power user — checks REO daily, manages several indexers):** Cannot deep-link, bookmark, or share an indexer or a filtered view — every session restarts from a manual search. No `/` shortcut; only 2 `:focus` rules in ~1,100 lines of CSS. No multi-select, so "show me Grace *and* Expired" — the actual daily question — is impossible. 98 rows unpaginated with a non-sticky header. No export, no copy-address. Filter and Sort both act on status and can silently contradict each other. Alex will read `active_indexers.json` directly, and once they do the dashboard has lost its power user.

**Sam (screen reader / low vision):** Every status indicator fails AA in the default theme (1.50–3.57:1). One `aria-label` in the document; zero `role`, `aria-sort`, `aria-pressed`, `aria-live` — filtering 98→0 is announced not at all. Sortable headers aren't buttons and aren't focusable. Search input has no label (placeholder only). All explanatory copy lives in `[data-tooltip]::after` pseudo-elements — invisible to screen readers, unreachable by keyboard and touch. Heading structure is h1→h3 with no heading on the table; no landmarks, no skip link. The `<h1>` announces as "cookie R E O". *(Corrected from Assessment A: `prefers-reduced-motion` IS handled — `gds.css:1603`, verified live under Playwright.)*

**Jordan (first-timer indexer, new to GIP-0079):** Lands on "🍪 REO" and a subtitle of acronyms. Nothing says what the oracle is or why it matters to them. Must decode four statuses from a legend placed *after* the controls, then hold them in working memory while scanning 98 rows past a header that scrolls away. Finds themselves "Unqualified" with no explanation of why and no remediation path — just a link 6,000px above. The wall of 98 identical pills reads as catastrophe rather than an un-provisioned testnet.

## Questions to Consider

1. **Who is this page for on any given load?** It answers the foundation's question ("is the oracle healthy") with the layout, and the indexer's question ("am I OK, what do I do") with nothing. If the indexer is primary, the page should open with a self-lookup that resolves to a single-subject view — and the 98-row table becomes the secondary surface, not the whole product.
2. **Why is there a legend at all?** A legend exists because the badge can't explain itself. If the badge said "Grace · 3 days left" / "Expired · lapsed 12 Jul" / "Unqualified · never renewed", the legend card, its four entries, and the working-memory tax all disappear — and the countdown GIP-0079 cares about appears on every row for free.
3. **If GDS is dark by default, and every status color passes in dark and fails in light — what is light theme for?** The measured evidence says this palette was designed for a dark canvas. Either default to dark and make light the deliberate variant, or design light's status pairs from scratch. Shipping light-first with a dark-first palette is the worst of both.
4. **What is the shape of this page when the answer is "everything is fine"?** Today, 98 healthy indexers render as 98 identical pills over 5,800px — the same visual load as 98 failures. A monitoring surface where the good state and the bad state cost the same to read isn't monitoring anything.
5. **The Telegram bot already knows which indexer a person cares about. Why doesn't the dashboard?** A single `?indexer=0x…` param turns a 7,109px table into a one-screen personal status page, and makes the alert→dashboard handoff continuous instead of dumping the user at the top of a wall.
